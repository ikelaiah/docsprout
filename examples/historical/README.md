# Historical Pages example

Choose this example when readers need documentation for current and older
releases. It demonstrates a small two-tag history:

- `v1.0.0` contains only its original `README.md`;
- `v1.1.0` adds modern configuration and an upgrade guide.

The current release must be the checked-out Git commit. Older pages always come
from their original tags.

## See the deterministic example test

From the DocSprout repository root, run:

```bash
python -m unittest tests.test_versions.VersionedBuildTests.test_historical_example_build_is_byte_for_byte_deterministic -v
```

The test creates both tags in a temporary repository, builds the site twice and
checks that every generated byte is identical.

## Use the pattern in your project

1. Copy `.github/workflows/documentation.yml`.
2. Copy the shape of `docs/versions.json`, using your own release labels and
   tags.
3. Commit the documentation and manifest before creating the current tag.
4. Run `docsprout check-release` and `docsprout build-all` locally.
5. In GitHub, set **Settings → Pages → Source** to **GitHub Actions**.
6. Push the commit and tag, then confirm the Documentation workflow is green.

Follow the full [pre-publish checklist](../../docs/pre-publish-checklist.md) for
the safe command order. Never change an older tag to repair its documentation;
publish a new patch release instead.
