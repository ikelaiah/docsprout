# Implementation Plan: v0.18.1 Responsive Prose Images

## Overview

Add DocKit's safe default responsive constraint for ordinary Markdown images
inside `.prose`, preserving intrinsic sizing for images that already fit and
preserving aspect ratio when oversized images shrink. Keep banners, custom CSS,
themes, content-width settings and every build mode compatible.

## Architecture decisions

- Put the rule in the existing shared `SITE_CSS` asset so normal, single-version
  and versioned builds receive identical behavior without a new configuration
  option.
- Use `max-width:100%` plus `height:auto`; do not set a global width or change
  inline-image display semantics.
- Extend the maintained visual fixture with a deliberately oversized SVG and a
  small badge so the fixture represents both sides of the intrinsic-sizing
  contract.
- Treat GitHub PR, merge, tag, release and Pages operations as a final release
  phase; report any unavailable remote authority rather than fabricating results.

## Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| A broad image rule enlarges badges or icons | High | Use `max-width`, never `width`; cover a small intrinsic image in tests. |
| SVG aspect ratio is lost while shrinking | High | Assert `height:auto` and, where browser tooling exists, rendered geometry. |
| Banner or custom CSS behavior changes | Medium | Preserve `.banner` and assert custom stylesheet load order. |
| A build mode misses the shared asset | Medium | Build normal, single-version and versioned fixtures and compare CSS. |
| Remote GitHub authority is unavailable | Medium | Complete local qualification and report exact unavailable release steps. |
