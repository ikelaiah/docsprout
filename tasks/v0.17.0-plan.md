# Implementation Plan: v0.17.0 — Qualification

## Overview

Turn DocKit's existing claims into tested, repeatable evidence. Python/OS/
package/ecosystem/accessibility qualification, not a feature release. The
release answers: can a maintainer trust DocKit installed normally and used on
supported Python versions, operating systems, repository shapes, packaging
formats and generated documentation sites?

The authoritative statement of intent is the roadmap's `v0.17 — Qualification`
entry, expanded below into concrete, verifiable tasks.

## Baseline (inspected and verified)

- Working tree on `main`, clean, at merge commit `9f000c2` (Release v0.16.2).
- Baseline release `v0.16.2` is an annotated tag on the merged `main` commit.
- Custom suite is Pure Python stdlib, 117 tests, 1 skip (Windows symlink
  privileges). Own docs: `check` clean, `audit --strict` 0 errors/0 warnings
  over 28 pages.
- Supported Python declared as `>=3.10`; CI only exercised Python 3.11 on
  Ubuntu. Windows/macOS, installed-package behaviour, wheel/sdist and broader
  repository shapes were not CI-proven.

## Architecture decisions

- Keep qualification in CI plus focused unittest modules and one installed-
  package runner script. No browser automation project: automate the stable
  structural/objective assertions; document a small manual keyboard matrix.
- The package-qualification job installs the built wheel and sdist into fresh
  virtual environments and runs the CLI journey from a directory outside the
  repository, so the product is exercised as users receive it.
- The `tests/__init__.py` src-injection convention stays for the in-checkout
  dev flow; subprocess CLI tests pass `PYTHONPATH=src` only when the package is
  not installed, so installed-package evidence is tested by the runner script.
- No runtime dependencies are added; the `build` frontend is CI/development
  tooling only.
- Fixes are limited to defects discovered by qualification (found during work:
  Python 3.10/3.11 `tarfile.extractall(filter=...)` incompatibility; Windows
  symlink test privilege dependence).

## Qualification failure policy

Qualification failures and bugs get a regression test plus the smallest correct
fix in scope. An architectural blocker that cannot be fixed safely within v0.17
is documented and left unreleased; a fake green qualification is never
accepted.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| 3.10/3.11-only runtime defect | Full stable CPython matrix; regression test for the discovered `tarfile.filter` issue |
| Windows privilege-dependent test hides a security bug | Junction fallback proves the same `resolve()` guard without elevation |
| Package works only in the source tree | CI installs wheel and sdist into fresh environments and runs outside the repo |
| Browser automation burden for accessibility | Structural automation + small documented manual matrix |
| Version-reference drift across pins and docs | Version-sensitive tests updated with the release metadata task |
