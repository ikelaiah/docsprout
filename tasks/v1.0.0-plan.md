# DocKit v1.0.0 stable-contract release plan

This plan turns the v0.18.1 contract candidate into the v1.0.0 release. It
intentionally preserves the historical v0.12 planning records in
`tasks/plan.md` and `tasks/todo.md`.

## Baseline

- Baseline source: merged v0.18.1 commit `a56a109bda183de570e38058802b5bda0aa7b7da`.
- Baseline tag: annotated `v0.18.1`, peeled to the same commit.
- Local preparatory commit preserved: `794a0ff` (canonical README badges).
- Baseline qualification: 194 unittest tests, `check`, strict audit, and a
  32-page local build pass; v0.18.1 CI and Pages deployment are green.

## Release work

1. Audit and explicitly freeze the five promises and v1 public compatibility
   boundary: schema-version-1 configuration, CLI/options/exit behavior,
   routes, machine-readable output, `--dk-*` tokens, custom CSS inclusion,
   workflow inputs, version metadata, and the 1.x compatibility policy.
2. Review maintainability and release procedures without broad refactoring;
   remove stale v0.18 wording, make the five promises and limitations
   discoverable, and update README, roadmap, changelog, contributor guidance,
   qualification evidence, migration guidance, architecture, and Pages docs.
3. Add lightweight regression coverage for canonical v1 documentation and
   metadata. Keep the existing implementation and tests authoritative; do not
   add a badge framework or unrelated features.
4. Prepare version `1.0.0`, stable classifier, v1 manifest/pins/examples, and
   the release workflow documentation. Build and inspect wheel and sdist from
   clean environments.
5. Rehearse clean-room adoption, customization, Pages setup/idempotency,
   immutable versioned builds, installed-package use, and the live Pages
   checks. Record automated, manual, and unavailable-browser evidence honestly.
6. Run the complete release gate, push `release/v1.0.0`, open the PR against
   `main`, inspect all required CI, repair only legitimate failures, merge,
   create the annotated `v1.0.0` tag and GitHub Release, then verify the tag,
   artifact metadata, Pages deployment, versioned documentation, and live
   site.

## Release decision rule

The release is complete only when the Five Promises have evidence, the
contract and migration guidance are explicit, all required automated checks
and clean-package rehearsals pass, the branch is green and merged, and the
published tag and documentation point at that merged commit. Full browser
geometry inspection is reported as unavailable if the browser MCP remains
unconfigured.
